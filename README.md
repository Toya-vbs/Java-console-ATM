# 一、项目功能简介
运行程序后会先读取存档文件，如果没有存档文件，则会提示**首次运行，无存档**。然后显示一级菜单。

## （1）一级菜单
1. 用户登录（Login）
2. 创建新用户（Create New User）
3. 退出（Exit）

输入操作前的数字序号换行即可执行对应操作。

### 注册用户规则
用户名和密码约束：
- 用户名、密码**不能为空、不能全为空格**
- 用户名禁止以 `__deleted_uid__` 开头
- 新用户名不可与已有用户重名

### 用户登录规则
输入用户名与正确密码即可登录；用户名不存在或密码错误均判定登录失败。
登录成功后展示当前用户用户名、uid，并进入二级菜单。

<p align="center"><img width="427" height="624" alt="image" src="https://github.com/user-attachments/assets/aa24200e-3ac4-427d-af00-d50cf9f06511" /></p>

### 程序退出规则
一级菜单输入`3`换行退出程序，自动将内存中所有用户信息**加密写入本地存档**。

### 调试模式
一级菜单输入带任意空格的`debug`可进入调试菜单；输入其他无效内容仅提示输入错误，无任何业务执行。

## （2）二级菜单

<p align="center"><img width="289" height="291" alt="image" src="https://github.com/user-attachments/assets/5d905204-adbd-4f10-b319-b69706720ae5" /></p>

1. **change password（修改密码）**
先输入旧密码，校验通过后输入两次新密码，两次一致则修改成功。
约束：新密码不能为空、不全为空格、**不可与旧密码一致**。

2. **query（查询余额）**
新用户默认余额为0.00元；界面以**元**展示，底层使用`long`类型以**分**存储，规避浮点精度问题。
余额上限：`9223372036854775807`分 = `92233720368547758.07`元；取钱后余额不可低于0.00元。

3. **withdraw（取钱）和 4. deposit（存钱）**
- 输入格式：仅支持数字+最多1个小数点，最多两位小数，无正负号
- 通用上限：单笔操作金额不超过`92233720368547758.07`元
- 取钱限制：取款金额 ≤ 当前账户余额
- 存钱限制：存款后总余额不可超出余额上限

5. **logout（用户登出）**
退出当前账号，返回一级菜单。

6. **change user name（修改用户名）**
输入新用户名完成修改，约束：
- 不可与原用户名一致
- 不可被其他用户占用
- 非空、非全空格、不以`__deleted_uid__`开头

7. **delete user（删除用户）**
1. 输入登录密码进行身份校验，密码错误直接删除失败
2. 校验通过弹出确认：`确认要删除吗？(y/N)`，仅输入小写`y`执行删除
3. 硬性条件：**账户余额必须为0.00元**，余额非0直接删除失败
4. 删除逻辑：用户状态标记为已删除，集合索引键修改为`__deleted_uid__+用户uid`
5. 后续使用该特殊键登录，直接判定用户已删除，登录失败
6. 删除成功自动退回一级菜单

# 二、其他系统功能
## 1. 密码加密存储
不用明文存储，采用**PBKDF2WithHmacSHA256**加盐哈希加密：
- 基于Java原生`javax.crypto`密码工具类实现
- 每个用户独立随机盐值，永久不变
- 注册：明文密码加密生成哈希值存入数据
- 登录：输入密码同规则加密比对哈希值，一致则登录成功

## 2. 用户数据持久化加密存档
1. 实体类实现序列化接口，定义固定序列化版本号`serialVersionUID`，通过对象序列化完成数据本地持久化
2. 采用**AES对称加密**，CBC工作模式+PKCS5Padding填充
3. 流程：内存对象序列化 → AES加密 → 写入`users.dat`存档
4. 启动流程：读取加密文件 → AES解密 → 反序列化恢复内存用户数据
5. 内置硬编码密钥，杜绝明文存档数据泄露

## 3. 定时自动计息功能
- 调度工具：`ScheduledExecutorService`单线程定时任务
- 执行规则：程序启动10秒后首次计息，之后**每10秒自动计息一次**
- 计息公式：
```
利息 = 账户余额(分) × 5 ÷ 100
新余额 = 原余额 + 利息
```
- 线程安全：遍历用户集合时对单个用户对象加`synchronized`锁
- 溢出防护：使用`Math.addExact`做安全加法，溢出捕获异常后直接赋值余额为最大值
- 过滤规则：已标记删除的用户自动跳过计息

# 三、系统架构设计
## 1. MVC三层架构
### （1）View 视图层：ATM.java
- 搭建所有层级交互菜单界面
- 接收控制台用户输入
- 统一做输入格式、内容合法性校验
- 调用控制层业务接口，展示操作结果与提示文案

### （2）Controller 控制层：Bank.java
- 承载项目全部核心业务逻辑
- 自定义统一错误状态码，向上返回执行结果与失败原因
- 核心业务：用户注册、登录校验、存取款、改密、改名、销户
- 附属功能：定时利息任务调度、加密文件读写管理

### （3）Model 数据模型层：UserModel + User
**User用户实体字段**
- 用户名：可修改，全局唯一登录标识
- 密码哈希值 + 独立盐值：加密登录凭证
- uid：全局唯一终身不变用户编号
- 账户状态：正常/已删除，预留扩展字段
- 账户余额：long类型，以分为单位存储
- 静态uid分配器：全局自增分配唯一编号

**UserModel**
统一管理全局用户集合，底层使用**ConcurrentHashMap**保证并发线程安全，统一封装用户数据增删改查。

## 2. 类调用层级关系
```
ATM 视图层
    ↓
Bank 业务控制层
    ↓
UserModel 数据管理层
    ↓
ConcurrentHashMap 线程安全集合
    ↓
User 用户实体类
```
